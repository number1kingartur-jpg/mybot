# KINGMODE Mini App

Приложение для Telegram: калькуляторы, программы тренировок, питание с учётом
съеденного. Те же формулы, что в боте, но интерфейсом вместо переписки.

## Что внутри

Навигация — нижняя панель на 5 разделов, как в нативном приложении.

| Раздел | Что делает | Источник в боте |
| --- | --- | --- |
| Знакомство | Анкета первого запуска: пол, возраст, рост, вес, активность, цель, место тренировок. Один раз — дальше данные подставляются во все разделы | — |
| Сегодня | Сводка: съедено / осталось, вес, тренд, последний 1ПМ, план тренировки + карточка активной программы с кнопкой «Выполнено» | собирает данные остальных разделов |
| Тренировка | Планы дом/зал A и B: шаги, ошибки, облегчённый вариант, видео; кнопка «Выполнил — записать» | `src/simple.ts`, `simple_done` |
| Питание · Съедено | Фото еды, справочник продуктов, ввод текстом, ручной ввод; переключение дней назад; прогресс к норме по ккал и БЖУ | `src/meal.ts`, `src/foods.ts`, таблица `meals` |
| Питание · Меню | Русское и тайское меню на день, состав приёмов, КБЖУ под личную норму, кнопка «Съел» пишет приём в дневник | `src/meals.ts` |
| Питание · Норма | Норма калорий и БЖУ под цель, доли макросов, разбивка по 4 приёмам | `src/nutrition.ts` → `calcMacros` |
| Расчёты · 1ПМ | Разовый максимум (среднее Эпли / Бжицки / Ландера) + таблица % | `src/calc/orm.ts` |
| Расчёты · Программа | 5/3/1, GZCLP, DUP, линейная, волновая — веса по неделям; кнопка «Сделать активной программой» | `src/calc/templates.ts`, `src/calc/periodization.ts` |
| Дневник | График веса, тренд за 28 дней, корректировка калорий по факту; записи общие с ботом | `src/nutrition.ts` → `weightTrendAdvice`, таблица `bodyweight` |

Экран «Сегодня» ничего не выдумывает: показывает только то, что реально посчитано
или записано. Нет записей веса — в плитке стоит прочерк, а не заглушка с числом.

## Два режима работы

| | Открыто из Telegram (бот раздаёт приложение) | Открыто в обычном браузере |
| --- | --- | --- |
| Расчёты, программы, тренировки | работают | работают |
| Фото еды, разбор текстом, справочник | работают | недоступны |
| Дневник еды | общий с чатом бота, дни назад листаются | ручной ввод за сегодня, хранится на устройстве |
| Дневник веса | общий с чатом бота | на устройстве; при первом входе из Telegram записи переносятся в базу |
| Активная программа и отметки тренировок | общие с чатом бота | недоступны |

Почему так: распознавание фото идёт через ключ Gemini, который нельзя держать в
клиентском коде, а `sendData` в Telegram передаёт максимум 4 КБ текста — фото туда
не влезет. Поэтому приложение общается с ботом по HTTP, а подлинность пользователя
подтверждает подпись `initData` (HMAC по токену бота, `src/webapp-auth.ts`).

## Файлы

```
webapp/
  index.html      каркас, подключение Telegram SDK
  css/app.css     дизайн-система: палитра и шрифты arturkingfitness.com
  js/api.js       связь с ботом: дневник еды, фото (сжатие на устройстве)
  js/engine.js    расчёты — порт формул из src/ (менять синхронно с ботом!)
  js/plans.js     готовые тренировки — порт src/simple.ts
  js/menus.js     меню на день — порт src/meals.ts
  js/app.js       экраны, навигация, состояние
```

Серверная часть живёт в боте: `src/server.ts` (HTTP + API) и `src/webapp-auth.ts`
(проверка подписи).

## Деплой: бот раздаёт приложение сам

Отдельный хостинг не нужен — HTTP-сервер поднимается вместе с ботом.

1. Задеплоить бота как обычно (push в `main` → Railway).
2. Railway → сервис бота → **Settings → Networking → Generate Domain**.
3. Всё. Адрес подхватится из `RAILWAY_PUBLIC_DOMAIN`, в логе старта появится
   `Mini App: https://…up.railway.app/ (домен Railway)`, кнопка «⚡️ Приложение»
   встанет первой в меню бота.

Проверка живости сервера: `GET /health` → `{"ok":true,"vision":true|false}`.

### Обязательно для дневника еды

| Переменная | Зачем |
| --- | --- |
| `DATA_PATH=/data/data.json` + Volume на `/data` | без этого база (еда, вес, программы) стирается при каждом redeploy |
| `GEMINI_API_KEY` | без ключа фото не распознаётся, приложение честно скажет об этом |

### Если статика всё-таки нужна отдельно

Приложение можно положить на GitHub Pages, тогда API останется на боте:

```bash
cd mybot
git subtree push --prefix webapp origin gh-pages
```

Адрес Mini App: `https://<логин>.github.io/<репозиторий>/?api=https://<домен-бота>`.
Параметр `api` говорит приложению, куда стучаться; CORS на сервере уже разрешён.
Вариант хуже: два места для обновления вместо одного.

## Локальная проверка

```bash
npm run build
node dist/index.js
```

Открыть `http://localhost:8080/`. Вне Telegram нет подписи `initData`, поэтому
приложение работает в локальном режиме: расчёты и ручной ввод еды есть, фото нет.
Вибрация и системная кнопка «назад» тоже не работают — навигация на нижней панели.

## API для приложения

Все запросы требуют заголовок `X-Telegram-Init-Data`. Без него — 401.

| Метод | Путь | Что делает |
| --- | --- | --- |
| GET | `/api/state?date=` | всё состояние человека одним ответом: приёмы за день, итоги, профиль, фото-лимит, дневник веса, активная программа, очередь тренировок |
| POST | `/api/meal/photo` | `{imageBase64}` → распознавание → запись в дневник |
| POST | `/api/meal/text` | `{text}` → справочник или модель → запись |
| POST | `/api/meal/food` | `{name, grams}` → расчёт по справочнику |
| POST | `/api/meal/manual` | `{name, kcal, proteinG, fatG, carbsG}` |
| DELETE | `/api/meal?id=` | удалить свою запись |
| GET | `/api/foods` | справочник продуктов |
| POST | `/api/nutrition` | сохранить профиль (норма едина для бота и приложения) |
| POST | `/api/bodyweight` | `{weightKg, date?}` — дата необязательна, будущее отклоняется |
| DELETE | `/api/bodyweight?date=` | удалить взвешивание |
| POST | `/api/program` | `{model, goal, weeks, lifts}` → программа считается **на сервере** и становится активной |
| POST | `/api/program/done` | записать тренировку дня, сдвинуть день, вернуть рекорд, если он есть |
| POST | `/api/workout/simple` | `{place?}` → отметка готовой тренировки, как кнопка «✅ Выполнил» в чате |
| POST | `/api/settings` | `{place}` — дом/зал, общее с ботом |

Приложение не присылает готовые веса программы: сервер пересчитывает их своим же
кодом (`src/calc/*`) по присланному вводу. Иначе подменённым запросом можно было бы
записать в базу план с любыми цифрами.

Запись даты: еда пишется только в текущий день (прошлые дни — просмотр), вес можно
записать за любой прошедший день.

## Доступ: пробный период

Сейчас включён пробный режим (`TRIAL_MODE`, по умолчанию `1`): недельного лимита фото
нет ни у кого, `/premium` ничего не продаёт и честно говорит, что покупать нечего.
Счётчики фото при этом пишутся — на них будет опираться платный вход.

| Переменная | Что делает |
| --- | --- |
| `TRIAL_MODE=1` (по умолчанию) | лимитов нет, Premium не продаётся |
| `TRIAL_MODE=0` | возвращается недельный лимит `MEAL_PHOTO_WEEK_LIMIT` (5) и продажа Premium в Stars |
| `MEAL_PHOTO_DAY_CAP=40` | дневная планка на фото, работает **всегда**, даже в пробном режиме |

Зачем планка в бесплатном режиме: ключи Gemini имеют суточную квоту на аккаунт. Без
планки один пользователь, гоняющий фото в цикле, выжигает квоту для всех остальных —
и все получают отказ. 40 фото в день нормальному человеку не нужны: это не лимит
монетизации, а защита сервиса. Владельца планка не режет. `MEAL_PHOTO_DAY_CAP=0` снимает
её полностью.

## Что дальше

- Фотопротокол прогресса (снимки раз в 2 недели, сравнение «до / сейчас») не сделан:
  нужны хранение картинок на Volume, подписанные ссылки на выдачу и правило удаления.
- История тренировок (список, рекорды, объём по движениям) в приложении не показана —
  данные в базе есть, экрана нет. В чате это `/progress` и `/records`.
- Ввод результатов силовой тренировки по подходам (как текстом в чате: «жим 100×5×3»)
  в приложении нет: отметка программы пишет запланированные цифры, а не фактические.

## Важно при правках формул

`js/engine.js` — копия расчётов из `src/`. Меняешь коэффициент в боте — меняй и здесь,
иначе приложение и бот начнут давать разные цифры на одних входных данных.

`js/menus.js` — состав меню и базовые КБЖУ один в один с `src/meals.ts`. Отличается
только база пересчёта порций: бот тянет к фиксированному калоражу цели (1600 / 2200 /
2800), приложение знает личную норму и считает от неё. Поэтому в приложении цифры
меню могут не совпадать с `/menu` в чате — это осознанно, а не рассинхрон.
